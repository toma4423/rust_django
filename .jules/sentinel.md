## 2025-02-12 - Critical CSRF Bypass Fixed
**Vulnerability:** The custom `CsrfValidation` guard in `src/csrf.rs` was silently bypassing verification for HTMX requests if the `X-CSRF-Token` header was omitted. Also, several delete and toggle endpoints (`delete_user`, `toggle_todo`, `delete_todo`) were lacking CSRF protection altogether.
**Learning:** In Rocket apps using custom request guards for security, fail-open logic (e.g., returning `Outcome::Success` when a required header is missing) can completely negate the intended protection. Furthermore, using a macro-based system for CRUD controllers can easily obscure the lack of proper parameter checks, such as verifying a `CsrfToken`.
**Prevention:** Ensure all security guards default to fail-close (`Outcome::Error`) if validation material is absent. Always check macro implementations to verify that mutating operations properly require and validate CSRF tokens, rather than assuming standard macro generation handles it implicitly.
